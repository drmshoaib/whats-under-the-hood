What's Under the Hood? · #04 · Week 4

Lecture 4: Naive Bayes

Part I: Mathematical Foundations and Classical Supervised Learning
Dr. Muhammad Shoaib · Applied Mathematics & Data Science · LinkedIn newsletter · every lecture follows the same 27 sections — use the sidebar to navigate.

The first three lectures were discriminative: linear and logistic regression model $P(y\mid x)$ or the boundary directly, and KNN reads the answer off nearby examples. Naive Bayes takes the opposite, generative route. It builds a probabilistic model of how each class produces a feature vector, then uses Bayes' theorem to turn that model into a class prediction. The word "naive" refers to a single simplifying assumption, that the features are conditionally independent given the class. The assumption is almost never literally true, yet the classifier works well in practice, especially for text. Understanding why a wrong assumption still gives good classifications is the main point of this lecture, and the lesson applies widely in machine learning: a model can be a poor description of reality and still be an effective decision rule.

1. Motivation and Problem Setting

The problem. Given a feature vector $x=(x_1,\dots,x_p)$, assign it to one of $M$ classes. We want $P(y=c\mid x)$ for each class $c$ and predict the most probable one. Naive Bayes attacks this by modelling how features arise within each class.

Discriminative versus generative. A discriminative model (logistic regression, KNN, SVM) learns $P(y\mid x)$ or the boundary directly. A generative model learns the joint $P(x,y)=P(x\mid y)P(y)$, a full account of how the data are produced, and derives $P(y\mid x)$ from it via Bayes' theorem. Generative models can generate synthetic data, marginalise over missing features, and often need less training data; discriminative models usually achieve lower error given enough data because they optimise exactly the quantity they are judged on. Naive Bayes is the simplest generative classifier in common use.

Why it was developed. The full generative approach requires modelling the joint distribution of all features within a class, $P(x_1,\dots,x_p\mid y)$. In $p$ dimensions this is infeasible: for binary features it needs $2^p-1$ parameters per class, far more than any dataset can estimate. Naive Bayes makes the problem tractable with the conditional-independence assumption, collapsing $2^p$ parameters to just $p$ per class. It became the default text classifier (spam filtering, document categorisation) because it is fast, needs little data, and copes with the large sparse feature spaces of language.

Where it sits. Naive Bayes is supervised, parametric, probabilistic and generative. It is the generative sibling of logistic regression (with shared class variances they have the same log-linear posterior form; §19) and a distant relative of the Gaussian mixture models and Gaussian processes to come (coming in Week 15 and coming in Week 17), all of which build on the same Bayesian machinery: priors, likelihoods, and posteriors.

Assumptions.

  1. Conditional independence: given the class, the features are independent: $P(x\mid y)=\prod_j P(x_j\mid y)$. This is "naive."
  2. A correct per-feature likelihood family: Gaussian for continuous features, multinomial for counts, Bernoulli for binary; the family must match the data (§3).
  3. Representative priors: the training class frequencies reflect the deployment class frequencies (or you set priors deliberately).
  4. Independent observations.

When reasonable / unreasonable. The independence assumption is reasonable when features carry largely non-redundant information (e.g. many weakly-correlated word indicators). It is unreasonable when features are strongly correlated or one feature is a near-duplicate of another. Naive Bayes then counts the shared evidence twice, which produces miscalibrated probabilities, though often still the correct ranking and hence correct classifications (§4.4). The chosen likelihood family must also match the data type.

2. Core Intuition

Bayes' theorem says: to find how probable a class is given the evidence, combine how probable that class is a priori with how well that class explains the evidence. Formally, posterior $\propto$ prior $\times$ likelihood.

Think of a spam filter. Before reading an email, you have a prior belief, say that 30% of mail is spam. Then you read the words. The word "viagra" is far more likely to appear in spam than in ham, so seeing it multiplies your belief towards spam; the word "meeting" pulls the other way. Naive Bayes multiplies together the evidence from every word (treating each word's contribution as independent, given the class) and combines it with the prior. Whichever class ends up with the higher product wins.

Why the "naive" multiplication works. In reality "free" and "money" co-occur in spam; they are not independent. Naive Bayes ignores this and multiplies their individual likelihoods anyway. This over-counts correlated evidence, so the resulting probability estimate is too extreme (over-confident). For the argmax decision, however, we need only that the correct class has the largest product; its magnitude is irrelevant. Over-confidence usually pushes the already-winning class further ahead without changing which class wins. So the classifier is right even though its probabilities are wrong.

Probabilistic intuition. Each class is a "generator" with its own recipe for producing features. Gaussian NB imagines each class draws each continuous feature from a bell curve with a class-specific mean and variance. Multinomial NB imagines each class is a weighted die rolled repeatedly to produce word counts. Classification picks the generator that most plausibly produced the observation.

Tiny numerical seed. Two classes equally likely a priori. Class A generates feature "1" 90% of the time; class B generates "1" 20% of the time. We observe "1". Posterior odds A:B $= (0.5\cdot0.9):(0.5\cdot0.2)=0.45:0.10$, so $P(A\mid1)=0.45/0.55\approx0.82$. We build a full multi-feature example in §6.

3. Mathematical Formulation

Notation. Feature vector $x=(x_1,\dots,x_p)$, class label $y\in\{1,\dots,M\}$. Let $\pi_c=P(y=c)$ be the class prior, and $P(x_j\mid y=c)$ the per-feature class-conditional likelihood.

Bayes' theorem.

$$ P(y=c\mid x)=\frac{P(x\mid y=c)\,P(y=c)}{P(x)}=\frac{P(x\mid y=c)\,\pi_c}{\sum_{c'}P(x\mid y=c')\,\pi_{c'}}. $$

The denominator $P(x)$ is the same for all classes, so for the decision it can be ignored; it is only a normaliser.

The naive conditional-independence assumption.

$$ P(x\mid y=c)=\prod_{j=1}^p P(x_j\mid y=c). $$

The classifier (MAP rule). Predict the class maximising the posterior, equivalently the (unnormalised) prior × likelihood product:

$$ \hat y = \arg\max_{c}\ \pi_c\prod_{j=1}^p P(x_j\mid y=c). $$

The log-space form (used in practice). Multiplying many small probabilities underflows to zero; work in logs, turning products into sums:

$$ \hat y=\arg\max_c\ \Big[\log\pi_c+\sum_{j=1}^p\log P(x_j\mid y=c)\Big]. $$

This is a linear function of the log-likelihood terms, which §7 and §19 use.

The three standard likelihood families

Gaussian NB (continuous features). Each feature is normally distributed within each class:

$$ P(x_j\mid y=c)=\frac{1}{\sqrt{2\pi\sigma_{cj}^2}}\exp\!\left(-\frac{(x_j-\mu_{cj})^2}{2\sigma_{cj}^2}\right), $$

with class-and-feature-specific mean $\mu_{cj}$ and variance $\sigma_{cj}^2$.

Multinomial NB (count features, e.g. word counts). Each class $c$ has a categorical distribution over the vocabulary with probabilities $\theta_{cj}$ ($\sum_j\theta_{cj}=1$). For a document with counts $x_j$:

$$ P(x\mid y=c)\propto\prod_{j=1}^p \theta_{cj}^{\,x_j},\qquad \theta_{cj}=\frac{\text{count of feature }j\text{ in class }c}{\text{total count in class }c}. $$

Bernoulli NB (binary features, e.g. word present/absent). Each feature is a coin flip with class-specific success probability $\theta_{cj}=P(x_j=1\mid y=c)$:

$$ P(x\mid y=c)=\prod_{j=1}^p \theta_{cj}^{\,x_j}(1-\theta_{cj})^{1-x_j}. $$

Note Bernoulli NB explicitly models feature absence (the $(1-\theta_{cj})$ term), unlike Multinomial NB.

Laplace (additive) smoothing. To avoid zero probabilities (a single unseen feature-value zeroes the whole product), add a pseudocount $\alpha$:

$$ \theta_{cj}=\frac{N_{cj}+\alpha}{N_c+\alpha\,K}, $$

where $N_{cj}$ is the count of feature $j$ in class $c$, $N_c$ the total in class $c$, and $K$ the number of possible values (vocabulary size for text). $\alpha=1$ is "Laplace smoothing"; $\alpha<1$ is "Lidstone."

4. Derivation

4.1 From the joint to the posterior

The joint distribution factors as $P(x,y)=P(y)P(x\mid y)$. The quantity we want, the posterior, follows from the definition of conditional probability:

$$ P(y\mid x)=\frac{P(x,y)}{P(x)}=\frac{P(y)P(x\mid y)}{P(x)}. $$

This is exact; it is Bayes' theorem. Everything "naive" enters only in how we model $P(x\mid y)$.

4.2 Why the independence assumption is necessary

Modelling $P(x\mid y=c)$ jointly is infeasible. Suppose all $p$ features are binary. The joint distribution over $p$ binary variables has $2^p$ possible outcomes, hence $2^p-1$ free parameters per class. With $p=1000$ (a small vocabulary) that is $2^{1000}\approx10^{301}$ parameters, unestimable from any dataset. The independence factorisation $P(x\mid y)=\prod_j P(x_j\mid y)$ replaces this with $p$ parameters per class (one per feature). This exponential-to-linear collapse is the entire reason Naive Bayes exists; the price is the (usually false) independence assumption.

4.3 Maximum-likelihood parameter estimates

The parameters are fitted by maximum likelihood, and the estimates are counting and averaging, with closed forms and no iteration.

Priors. Maximising the likelihood of the class labels gives the empirical frequencies:

$$ \hat\pi_c=\frac{N_c}{N},\qquad N_c=\#\{i:y_i=c\}. $$

Gaussian NB. Maximising the Gaussian likelihood for the points in class $c$ gives the sample mean and variance per feature (exactly as in fitting a normal distribution):

$$ \hat\mu_{cj}=\frac{1}{N_c}\sum_{i:y_i=c}x_{ij},\qquad \hat\sigma_{cj}^2=\frac{1}{N_c}\sum_{i:y_i=c}(x_{ij}-\hat\mu_{cj})^2. $$

Multinomial / Bernoulli NB. Maximising the multinomial/Bernoulli likelihood gives the smoothed relative frequencies $\hat\theta_{cj}=(N_{cj}+\alpha)/(N_c+\alpha K)$ of §3. The pseudocount $\alpha$ is equivalent to placing a Dirichlet/Beta prior on the parameters and taking the posterior mean, so smoothing is a Bayesian regularisation (§8).

4.4 Why a wrong assumption still classifies well (Domingos–Pazzani)

Consider two classes and write the log-posterior-odds:

$$ \log\frac{P(y{=}1\mid x)}{P(y{=}0\mid x)}=\log\frac{\pi_1}{\pi_0}+\sum_{j=1}^p\log\frac{P(x_j\mid y{=}1)}{P(x_j\mid y{=}0)}. $$

We classify as class 1 when this sum is positive. Now suppose the true features are correlated, so the independence assumption is false. The magnitude of the sum will be wrong: correlated features contribute their evidence more than once, inflating the sum and making the probability estimate over-confident (pushed towards 0 or 1). The sign of the sum, which determines the classification, is often still correct, because the direction in which each feature pushes is usually right even when the amount is exaggerated.

Domingos and Pazzani (1997) made this precise: under zero-one loss, Naive Bayes is optimal in a much wider region than the independent case, namely whenever the dependencies between features cancel or leave the sign of the decision unchanged. Good probability estimation and good classification are different goals, and a model can fail the first and pass the second.

5. Algorithm

TRAINING (closed-form counting and averaging; no iteration):
  Input: {(x_i, y_i)}, smoothing α, likelihood family
  1. For each class c:
       π̂_c = N_c / N                             # class prior
  2. For each class c and feature j, estimate the likelihood parameters:
       Gaussian:    μ̂_cj = mean, σ̂²_cj = variance of feature j over class-c points
       Multinomial: θ̂_cj = (N_cj + α) / (N_c + αK)     # smoothed word frequencies
       Bernoulli:   θ̂_cj = (N_cj + α) / (N_c + 2α)     # smoothed presence probability
  Output: priors and per-class-per-feature likelihood parameters

PREDICTION (work in log space to avoid underflow):
  Input: query x
  1. For each class c compute the log-score:
       score_c = log π̂_c + Σ_j log P(x_j | y=c)   # linear in log-likelihoods
  2. ŷ = argmax_c score_c
  3. Probabilities (optional): softmax of the scores,
       P(y=c | x) = exp(score_c) / Σ_c' exp(score_c')

Inputs: labelled data, likelihood family, smoothing $\alpha$, optional class priors. Initialisation / stopping: none; training is a single counting pass. Outputs: the predicted class and posterior probabilities (typically over-confident, §8).

6. Worked Numerical Example

A tiny spam filter with two binary word features. Training data (14 emails):

Class# emails# with "free"# with "meeting"
Spam651
Ham816

Use Bernoulli NB with Laplace smoothing $\alpha=1$ ($K=2$ values per feature: present/absent). Classify a new email containing "free" (=1) but not "meeting" (=0).

Step 1: priors.

$$ \hat\pi_{\text{spam}}=\tfrac{6}{14}=0.4286,\qquad \hat\pi_{\text{ham}}=\tfrac{8}{14}=0.5714. $$

Step 2: smoothed likelihoods $\hat\theta_{cj}=\dfrac{N_{cj}+1}{N_c+2}$ (probability the word is present):

$$ \theta_{\text{spam,free}}=\tfrac{5+1}{6+2}=\tfrac{6}{8}=0.75,\qquad \theta_{\text{spam,meet}}=\tfrac{1+1}{6+2}=\tfrac{2}{8}=0.25, $$ $$ \theta_{\text{ham,free}}=\tfrac{1+1}{8+2}=\tfrac{2}{10}=0.20,\qquad \theta_{\text{ham,meet}}=\tfrac{6+1}{8+2}=\tfrac{7}{10}=0.70. $$

Step 3: likelihood of the observation (free=1, meeting=0). Bernoulli uses $\theta$ for present features and $(1-\theta)$ for absent:

$$ P(x\mid\text{spam})=\theta_{\text{spam,free}}\cdot(1-\theta_{\text{spam,meet}})=0.75\times0.75=0.5625, $$ $$ P(x\mid\text{ham})=\theta_{\text{ham,free}}\cdot(1-\theta_{\text{ham,meet}})=0.20\times0.30=0.0600. $$

Step 4: unnormalised posteriors (prior × likelihood).

$$ \text{spam}:\ 0.4286\times0.5625=0.2411,\qquad \text{ham}:\ 0.5714\times0.0600=0.0343. $$

Step 5: normalise.

$$ P(\text{spam}\mid x)=\frac{0.2411}{0.2411+0.0343}=\frac{0.2411}{0.2754}=0.875,\qquad P(\text{ham}\mid x)=0.125. $$

Decision: classify as spam with posterior $\approx0.88$. The single word "free" (present in 5/6 spam but only 1/8 ham) combined with the absence of "meeting" strongly favours spam. The Bernoulli model used both the presence of "free" and the absence of "meeting" as evidence; Multinomial NB would ignore the absence.

Log-space check (Step 5 alternative). $\log(0.2411)=-1.423$, $\log(0.0343)=-3.373$; the spam score exceeds the ham score by $1.95$ nats, and $\text{softmax}=(e^{-1.423},e^{-3.373})/\text{sum}=(0.875,0.125)$, the same result computed without underflow.

7. Geometry and Visual Interpretation

Gaussian NB carves space with quadratic (or linear) boundaries. Each class is a probability "hill", a product of per-feature Gaussians whose contours in 2D are axis-aligned ellipses (independence forces a diagonal covariance, so there is no tilt). Classification assigns each point to the class whose hill is highest there. Where two Gaussian hills of different variances meet, the boundary is a quadratic curve (a conic); where the variances are equal across classes, the quadratic terms cancel and the boundary is a straight line or hyperplane. In that special case Gaussian NB coincides with Linear Discriminant Analysis (LDA) restricted to a diagonal shared covariance. A good visualisation: two sets of concentric axis-aligned ellipses (one per class), with the decision boundary running through the points of equal height.

The log-linear view. Writing the log-posterior-odds (§4.4) shows the decision function is linear in the log-likelihood terms. For Multinomial/Bernoulli NB this makes the decision boundary linear in the feature space, so Naive Bayes is a linear classifier, closely paralleling logistic regression (§19). The difference is how the linear weights are chosen: NB sets them by generative counting; logistic regression sets them by discriminative optimisation.

Independence = axis-aligned. The geometric signature of the naive assumption is the absence of tilt: the class densities cannot capture diagonal correlation structure, so their contours are always aligned to the feature axes. When the true class clouds are tilted (correlated features), NB's axis-aligned ellipses misfit, which is the visual explanation of its miscalibration.

8. Statistical Interpretation

A generative model with MLE parameters. Naive Bayes posits a full generative story $P(x,y)$ and estimates its parameters by maximum likelihood, with closed-form counts and moments (§4.3). Because each parameter is estimated from only the data in its class using a simple sufficient statistic (counts, means, variances), the estimates are low-variance and consistent for the assumed model, and stable even with little data. This data-efficiency is the statistical upside of the strong assumption.

Bias from the assumption. The independence assumption introduces model bias: the fitted joint $P(x\mid y)$ is systematically wrong whenever features are correlated. This bias shows most clearly in calibration: the posterior probabilities are typically pushed towards 0 or 1 (over-confident), because correlated evidence is counted repeatedly. So NB is a good classifier but an unreliable probability estimator (§14, §16).

Smoothing as Bayesian inference. Adding pseudocount $\alpha$ is the posterior mean under a Dirichlet($\alpha$) prior on the categorical parameters (Beta for Bernoulli). It regularises the estimates away from the extreme 0/1 values that unseen events would otherwise force, a small dose of prior belief that prevents a single unseen feature from vetoing a class.

Priors and decision theory. The class priors $\pi_c$ let you inject known base rates and, combined with a loss matrix, produce Bayes-optimal decisions under asymmetric costs (e.g. missing spam vs blocking real mail). This decision-theoretic footing is a strength of the generative framing.

9. Training and Optimisation

No iterative optimisation: training is closed-form counting. Unlike logistic regression (iterative), SVM (quadratic program), or neural nets (gradient descent), Naive Bayes has an analytic maximum-likelihood solution: count class frequencies, count/average feature statistics per class, apply smoothing. A single pass over the data suffices. There is no loss surface to descend, no convergence to worry about, no initialisation, no learning rate.

Consequences.

  • Fast training: $O(np)$, one sweep to accumulate counts (§12).
  • Trivial online updates: counts are additive, so streaming data increments the sufficient statistics; Naive Bayes is naturally incremental (scikit-learn exposes partial_fit).
  • No local minima, fully deterministic: the same data always yields the same model.

The only "tuning" is the smoothing parameter $\alpha$ (and the choice of likelihood family), selected by cross-validation. In that sense Naive Bayes has almost no optimisation to speak of, which is why it is such a fast baseline.

10. Hyperparameters

$\alpha$, the additive (Laplace/Lidstone) smoothing strength.

  • Mathematically: the pseudocount added to every feature-value count; equivalently the Dirichlet/Beta prior strength (§8).
  • Increasing $\alpha$: pulls all likelihood estimates towards the uniform distribution → more bias, less variance; smooths over rare features, but too large a value washes out real signal and weakens the classifier towards the prior.
  • Decreasing $\alpha$ (towards 0): trusts the raw counts → less bias, more variance; risks zero/near-zero probabilities from unseen feature-values that can veto a class or make probabilities unstable.
  • Guidance: $\alpha=1$ is a safe default; tune on a log grid (e.g. $10^{-3}$ to $10$) by CV, especially for large sparse vocabularies where the right $\alpha$ matters.

Likelihood family (the biggest "hyperparameter"). Gaussian (continuous), Multinomial (counts/TF or TF-IDF), Bernoulli (binary presence). Choosing wrongly (e.g. Gaussian on word counts) hurts performance badly. This is a modelling decision made from the data type; grid search is for $\alpha$.

Class priors (class_prior / fit_prior). Use empirical frequencies, a uniform prior, or hand-set priors to reflect deployment base rates or cost asymmetries (§8). Setting a uniform prior can help under training-set imbalance that won't hold at deployment.

Binarisation threshold (Bernoulli NB, binarize). The cutoff that maps continuous/count features to 0/1 before applying the Bernoulli model; it defines what "present" means.

11. Bias–Variance Behaviour

  • High bias by design: the independence assumption and simple per-feature likelihoods make Naive Bayes a high-bias, low-variance model. It cannot represent feature interactions or correlation structure, so it underfits complex boundaries, but it is stable and rarely overfits.
  • Low variance is its advantage with small $n$ or large $p$: because it estimates only $O(Mp)$ simple statistics, the estimates are stable even when $n$ is small or $p$ is very large (text). This is why NB often beats lower-bias models such as logistic regression when data are scarce: the variance saving outweighs the bias cost.
  • Underfitting dominates its failure mode: it will plateau below the achievable accuracy when correlations carry real signal. Adding more data helps little once the bias floor set by the assumption is reached; the remedy is a richer model.
  • Overfitting is rare but possible with $\alpha\to0$ on sparse data (unseen values create unstable extreme probabilities); smoothing regularises this away.
  • Asymptotic comparison to logistic regression (Ng & Jordan, 2001): NB has higher asymptotic error (bias) but converges to its (worse) limit faster, with $O(\log p)$ samples against $O(p)$ for logistic regression. So NB wins in the small-$n$ regime, logistic regression overtakes it as $n$ grows.

12. Computational Complexity

Let $n$ = samples, $p$ = features, $M$ = classes.

  • Training: $O(np)$, a single pass accumulating counts and moments. Among the fastest classifiers to train; it scales to millions of documents.
  • Prediction: $O(Mp)$ per example: evaluate $p$ log-likelihoods for each of $M$ classes and take the argmax. For Multinomial NB on sparse text only the nonzero features contribute, so the cost is $O(M\cdot\text{nnz})$; Bernoulli NB still needs every feature, since absence is evidence.
  • Memory: $O(Mp)$: one parameter set (mean/variance or $\theta$) per class per feature. Tiny compared to KNN's $O(np)$; the training data is discarded after counting.
  • Online updates: $O(p)$ per new sample (increment counts), so the model is naturally streaming.

Scalability consequences: Naive Bayes is among the cheapest supervised classifiers to train, serve and update, which matters for very large, high-dimensional or streaming text data and is the reason it remains a standard first baseline.

13. Data Preparation

  • Choose the likelihood to match the data type (the most important prep decision): Gaussian for continuous, Multinomial for counts/TF-IDF, Bernoulli for binary presence. Mixed types can be handled by combining likelihoods (or discretising).
  • Text vectorisation (for Multinomial/Bernoulli): tokenise, build a bag-of-words count matrix (CountVectorizer) or TF-IDF (TfidfVectorizer, which works well with Multinomial NB despite being non-integer). Stop-word removal and n-grams can help.
  • Smoothing is required for sparse categorical/text features to avoid zero-probability vetoes (§3).
  • Feature scaling is unnecessary. NB models each feature's distribution separately, so an affine rescaling $x_j\mapsto ax_j+b$ of a Gaussian feature changes only its estimated $\mu$ and $\sigma$ and leaves the decision unchanged (apart from the small var_smoothing term, which is tied to the largest feature variance). A nonlinear transform such as a log does change the Gaussian fit and the decisions. (Contrast KNN/SVM, where scaling is critical.)
  • Redundant/correlated features hurt because they violate independence and are double-counted; consider removing near-duplicate features or decorrelating with PCA, though PCA replaces the natural per-feature likelihoods, so it is a trade-off.
  • Continuous features that are non-Gaussian: transform towards normality (log, Box–Cox) for Gaussian NB, or discretise into bins and use Multinomial/categorical NB.
  • Missing values. In principle a generative model can skip the missing feature's term in the product (marginalise it out), an advantage over discriminative models. scikit-learn's estimators do not implement this and reject NaN inputs, so in practice you impute first or write the marginalisation yourself.
  • Class imbalance: the prior encodes it directly; adjust class_prior or use costs if the training balance won't match deployment.

14. Evaluation

Evaluate as any classifier, with one caveat about probabilities.

  • Accuracy, precision, recall, F1: standard; F1 and precision-recall under imbalance (Lecture 2).
  • ROC-AUC / PR-AUC: NB's rankings are often good even when its probabilities are not, so AUC can look strong. PR-AUC for rare positives (e.g. spam).
  • Log-loss and calibration: read with care. Because NB is typically over-confident (probabilities pushed to 0/1 by double-counted correlated evidence), its log-loss and Brier score can be poor even when accuracy is high. A reliability diagram typically shows a curve flatter than the diagonal: predictions near 1 are realised less often than stated and predictions near 0 more often (Niculescu-Mizil and Caruana, 2005).

Why metrics mislead for NB specifically: the model's headline metric (accuracy) can be excellent while its probabilities are near-useless as calibrated risk estimates. If you need trustworthy probabilities (for thresholding by expected cost, or downstream decisions), calibrate NB (Platt or isotonic on a held-out set) and evaluate calibration explicitly; the raw posteriors should not be used as risk estimates.

15. Validation Strategy

  • Stratified $k$-fold CV: the default, preserving class balance; used to tune $\alpha$ and choose the likelihood family.
  • Train/test split for large corpora; keep a final untouched test set.
  • Grouped CV when documents cluster (same author/thread) to avoid leakage from near-duplicates.
  • Time-aware validation for evolving text (spam adapts over time): train on the past, test on the future; concept drift affects NB text models like any other.

Leakage risks: fit the vectoriser (vocabulary, IDF) inside each fold via a Pipeline; fitting TfidfVectorizer on the full corpus before splitting leaks test-set vocabulary/statistics. Also ensure the smoothing and priors are estimated only on training folds.

16. Diagnostics

  • Calibration / reliability plot: the key NB diagnostic; expect over-confidence (predictions clustered near 0 and 1). If probabilities matter, this tells you to calibrate.
  • Confusion matrix at the operating threshold.
  • Per-feature log-likelihood ratios: inspect $\log\frac{P(x_j\mid c_1)}{P(x_j\mid c_0)}$ per feature to see which features (words) drive decisions; NB is highly interpretable this way (the "most spammy words").
  • Gaussian-fit check (Gaussian NB): histogram or Q–Q plot of each continuous feature within each class; strong non-normality signals a wrong likelihood choice, so transform or switch family.
  • Correlation heatmap: heavy feature correlation warns that the independence assumption (and thus calibration) is badly violated.
  • Zero-count audit: check for features with zero counts in a class pre-smoothing; confirms smoothing is doing its job.
  • Learning curve: NB often plateaus early (bias floor); a flat curve well below a competitor's signals underfitting from the assumption.

17. Strengths

  • Extremely fast and cheap. $O(np)$ closed-form training, $O(Mp)$ prediction, $O(Mp)$ memory (data discarded); trains and serves at scale and updates online.
  • Excellent with little data / many features. Estimating only $O(Mp)$ simple statistics makes it low-variance; it often outperforms lower-bias models when $n$ is small or $p\gg n$ (its natural home: text).
  • Handles high-dimensional sparse data natively. The independence factorisation is perfectly suited to bag-of-words: thousands of features, each contributing an independent log-likelihood term.
  • Tolerant of irrelevant features. A feature with similar distributions across classes contributes near-zero to the log-odds and is effectively ignored, so no explicit selection is needed.
  • Interpretable. Per-feature log-likelihood ratios directly reveal which features push towards which class (the "spammy words").
  • Missing data can be marginalised out. A missing feature's term can be dropped from the product, a benefit of the generative form (not implemented in scikit-learn; §13).
  • Principled decision theory. Priors + a loss matrix give Bayes-optimal decisions under asymmetric costs.
  • Correct classifications despite wrong probabilities. The sign-preservation property (§4.4) means it classifies well even when the independence assumption fails.

18. Weaknesses and Failure Modes

  • Miscalibrated (over-confident) probabilities. Correlated features are double-counted, pushing posteriors towards 0/1. Example: a spam email containing "free", "free!!!", and "FREE" (near-duplicate features) yields a posterior very close to 1; the confidence is unjustified even if the label is right. Calibrate before using the numbers.
  • Independence-violation bias. When correlations carry real, non-redundant signal, NB cannot use it and underperforms. Example: features "temperature" and "humidity" jointly determine an outcome via their interaction; NB, treating them independently, misses it.
  • Zero-frequency problem (without smoothing). A single feature-value unseen in a class gives $P=0$, zeroing the entire product and vetoing the class regardless of other evidence. Smoothing is essential.
  • Wrong likelihood family. Gaussian NB on heavily skewed or multimodal features fits poorly; using Multinomial on continuous data is meaningless. The family is an easily mistaken choice.
  • Bias floor / underfitting. Accuracy plateaus below achievable levels when interactions matter; more data will not help.
  • Continuous-feature sensitivity. Gaussian NB assumes unimodal, symmetric per-class features; violations degrade it silently.
  • Sensitive to skewed priors at deployment. If training class balance differs from deployment, the priors mislead; set them deliberately.

NB vs Logistic Regression (the canonical pairing). They are a generative–discriminative pair: Gaussian NB with class-shared variances (and Multinomial or Bernoulli NB) has the same log-linear functional form for $P(y\mid x)$ as logistic regression, but the weights are estimated differently, NB by generative counting and LR by discriminative likelihood maximisation. Ng & Jordan (2001): NB reaches its (higher) asymptotic error faster (needs ~$O(\log p)$ samples), LR reaches its (lower) asymptotic error slower (~$O(p)$). So NB wins with little data, LR wins with plenty. LR also gives calibrated probabilities and handles correlated features; NB is faster and needs less data.

NB vs LDA/QDA. All three are generative Gaussian classifiers. Gaussian NB assumes a diagonal covariance (independent features → axis-aligned ellipses); LDA assumes a full, shared covariance (tilted but identical-shape ellipses → linear boundary); QDA assumes a full, per-class covariance (quadratic boundary). NB is the most constrained (most bias, least variance), QDA the least. Choose NB when $p$ is large or $n$ small (full covariances cannot be estimated); LDA/QDA when you can afford to model correlations.

NB vs KNN. Both are simple and assumption-light in different ways: NB assumes a parametric per-feature likelihood and scales to high $p$; KNN assumes only local smoothness but collapses in high $p$ (curse of dimensionality). For sparse high-dimensional text, NB is usually far better than KNN.

20. When I Should Use It

Use Naive Bayes when:

  • You are doing text classification (spam, sentiment, topic), its traditional home.
  • Data are high-dimensional or sparse, or training data are limited; low variance pays off.
  • You need a fast, cheap baseline to build, serve and update online.
  • Features are plausibly conditionally independent or carry largely non-redundant evidence.
  • You need interpretable per-feature evidence.
  • You care about the ranking or decision more than the exact probability values.

Avoid (or calibrate/replace) Naive Bayes when:

  • You need well-calibrated probabilities without post-hoc calibration.
  • Features are strongly correlated and those correlations carry the signal; use logistic regression, trees or gradient boosting.
  • Feature interactions are essential to the target.
  • You have abundant data and want the lowest achievable error; discriminative models will overtake it.
  • Continuous features are strongly non-Gaussian or multimodal and cannot be transformed.

21. Python Implementation From Scratch

import numpy as np

class GaussianNBScratch:
    """Gaussian Naive Bayes from NumPy: closed-form MLE, log-space prediction."""

    def __init__(self, var_smoothing=1e-9):
        self.var_smoothing = var_smoothing   # tiny floor to avoid divide-by-zero
        self.classes_ = None
        self.priors_ = None                  # log π_c
        self.means_ = None                   # μ_cj
        self.vars_ = None                    # σ²_cj

    def fit(self, X, y):
        X = np.asarray(X, float)
        y = np.asarray(y)
        self.classes_ = np.unique(y)
        n, p = X.shape
        M = len(self.classes_)

        self.means_  = np.zeros((M, p))
        self.vars_   = np.zeros((M, p))
        self.priors_ = np.zeros(M)

        # Closed-form MLE: per-class mean, variance and prior; counting and averaging only.
        eps = self.var_smoothing * X.var(axis=0).max()
        for k, c in enumerate(self.classes_):
            Xc = X[y == c]
            self.means_[k]  = Xc.mean(axis=0)                     # μ_cj
            self.vars_[k]   = Xc.var(axis=0) + eps                # σ²_cj (smoothed)
            self.priors_[k] = np.log(Xc.shape[0] / n)            # log π_c
        return self

    def _log_likelihood(self, X):
        # log of the per-feature Gaussian, summed over features (independence).
        # log N(x; μ, σ²) = −½ log(2πσ²) − (x−μ)²/(2σ²)
        M = len(self.classes_)
        log_lh = np.zeros((X.shape[0], M))
        for k in range(M):
            var = self.vars_[k]
            term = -0.5 * np.log(2 * np.pi * var)                 # normalising constant
            term = term - (X - self.means_[k]) ** 2 / (2 * var)   # exponent
            log_lh[:, k] = term.sum(axis=1) + self.priors_[k]     # Σ_j + log prior
        return log_lh

    def predict(self, X):
        X = np.asarray(X, float)
        return self.classes_[np.argmax(self._log_likelihood(X), axis=1)]

    def predict_proba(self, X):
        X = np.asarray(X, float)
        log_lh = self._log_likelihood(X)
        # Softmax with the log-sum-exp trick for numerical stability.
        log_lh -= log_lh.max(axis=1, keepdims=True)
        probs = np.exp(log_lh)
        return probs / probs.sum(axis=1, keepdims=True)

# --- demo ---------------------------------------------------------
from sklearn.datasets import load_iris
X, y = load_iris(return_X_y=True)
model = GaussianNBScratch().fit(X, y)
print("accuracy:", (model.predict(X) == y).mean())

Correspondence to the maths.

  • means_, vars_, priors_ are the closed-form MLE estimates $\hat\mu_{cj},\hat\sigma_{cj}^2,\hat\pi_c$ of §4.3: counting and averaging, no iteration.
  • _log_likelihood computes $\log\pi_c+\sum_j\log P(x_j\mid c)$ from §3, summing the per-feature log-Gaussians (the independence assumption made concrete by the .sum(axis=1)).
  • predict is the argmax of §3; predict_proba applies the log-sum-exp softmax (§5), the numerically stable normalisation.

(A Multinomial NB from scratch is shorter still: accumulate per-class feature-count sums, add $\alpha$, normalise to get $\theta_{cj}$, and score with $\sum_j x_j\log\theta_{cj}+\log\pi_c$.)

23. Library Parameters Mapped to Mathematics

sklearn.naive_bayes.MultinomialNB / BernoulliNB

  • alpha: the additive smoothing pseudocount $\alpha$ (§3): $\hat\theta_{cj}=(N_{cj}+\alpha)/(N_c+\alpha K)$. Larger $\alpha$ → estimates pulled towards uniform (more bias, less variance); $\alpha\to0$ → raw counts (risk of zero-probability vetoes). The Dirichlet-prior strength of §8.
  • fit_prior: whether to learn class priors $\hat\pi_c=N_c/N$ from data (True) or use a uniform prior (False); toggles the $\log\pi_c$ term.
  • class_prior: explicitly set the priors $\pi_c$ (e.g. to match deployment base rates or encode costs, §8).
  • binarize (BernoulliNB): threshold to convert features to 0/1 before the Bernoulli likelihood; defines "present" (§10).

sklearn.naive_bayes.GaussianNB

  • var_smoothing: a fraction of the largest feature variance added to every $\hat\sigma_{cj}^2$ for numerical stability; prevents a near-zero variance from producing an infinitely-peaked Gaussian and exploding log-likelihoods (the eps in §21).
  • priors: user-specified class priors $\pi_c$, as above.

Note on absent parameters. There is no learning rate, no regulariser $C$, no iteration count, because training is closed-form (§9). The only real knobs are the smoothing, the priors, and (implicitly, by choosing the estimator class) the likelihood family.

24. Common Interview Questions

1. What exactly is "naive" about Naive Bayes, and why do we accept it?
The assumption that features are conditionally independent given the class, $P(x\mid y)=\prod_j P(x_j\mid y)$. We accept it because modelling the full joint needs $O(2^p)$ parameters per class (infeasible), while the factorisation needs only $O(p)$, an exponential-to-linear collapse that makes the model estimable and fast.

2. Derive the Naive Bayes decision rule from Bayes' theorem.
$P(y{=}c\mid x)\propto P(y{=}c)P(x\mid y{=}c)=\pi_c\prod_j P(x_j\mid y{=}c)$ (dropping the class-independent normaliser and applying independence). Predict $\arg\max_c$ of this, or of its log $\log\pi_c+\sum_j\log P(x_j\mid c)$.

3. Why does Naive Bayes classify well even when the independence assumption is false?
Classification depends only on the sign of the log-posterior-odds, not its magnitude. Correlated features distort the magnitude (making probabilities over-confident) but usually preserve the sign, so the argmax, the class prediction, remains correct even though the probability is wrong (Domingos–Pazzani).

4. What is the zero-frequency problem and how does smoothing fix it?
If a feature-value never appears with a class in training, its estimated likelihood is 0, which zeroes the entire product and vetoes that class regardless of other evidence. Laplace/Lidstone smoothing adds a pseudocount $\alpha$: $\hat\theta=(N_{cj}+\alpha)/(N_c+\alpha K)$, guaranteeing nonzero probabilities. It equals the posterior mean under a Dirichlet prior.

5. When should you use Gaussian vs Multinomial vs Bernoulli NB?
Gaussian for continuous features (models mean/variance per class); Multinomial for count/frequency features like word counts or TF-IDF; Bernoulli for binary presence/absence (and it uses feature absence as evidence). Matching the family to the data type is critical.

6. Why is Naive Bayes so effective for text classification?
Text is extremely high-dimensional and sparse (thousands of word features); NB's per-feature factorisation handles this natively, needs little data (low variance), trains in one pass, and words carry largely non-redundant evidence, so the independence assumption is tolerable and the model is fast and strong.

7. Explain the generative vs discriminative distinction using NB and logistic regression.
NB (generative) models the joint $P(x,y)=P(x\mid y)P(y)$ and derives $P(y\mid x)$; LR (discriminative) models $P(y\mid x)$ directly. With shared class variances they have the same log-linear posterior form but estimate the parameters differently. NB needs less data and can generate/handle missing features; LR usually achieves lower error with enough data and is better calibrated.

8. Are Naive Bayes probabilities trustworthy? Why or why not?
Usually not: they are over-confident (pushed towards 0/1) because correlated features are double-counted, violating independence. The rankings/labels are often fine, but the probability values need post-hoc calibration (Platt/isotonic) before use in cost-sensitive decisions.

9. How does Naive Bayes handle missing feature values?
In principle, being generative, it can marginalise out a missing feature by omitting its term from the product $\prod_j P(x_j\mid c)$, using only the observed features; discriminative models generally cannot do this without imputation. scikit-learn's implementations do not support this, so missing values must be imputed first.

10. Compare the bias–variance and sample-complexity of NB and logistic regression.
NB is higher-bias (the assumption) but lower-variance; it converges to its (worse) asymptotic error with far fewer samples (~$O(\log p)$ vs $O(p)$). So NB wins in the small-data regime and LR overtakes it as data grow (Ng & Jordan, 2001).

11. (Debugging) Your Gaussian NB performs poorly on a skewed continuous feature. What's wrong and what do you do?
Gaussian NB assumes each feature is normally distributed within each class; a strongly skewed/multimodal feature violates this, so its likelihood is misestimated. Fix by transforming towards normality (log/Box–Cox), discretising into bins with Multinomial NB, or switching to a model without the Gaussian assumption.

12. Why doesn't Naive Bayes need feature scaling?
It models each feature's distribution separately (its own $\mu,\sigma$ or $\theta$), so an affine rescaling of a feature only rescales its estimated parameters, with no effect on the decision (a nonlinear transform does change the fit). Unlike KNN/SVM, distances across features are never combined, so scale is irrelevant.

25. Common Misconceptions

  1. "Naive Bayes assumes features are independent." It assumes features are conditionally independent given the class, a weaker (though still strong) statement. Marginally, the features it uses can be correlated.
  2. "Because the assumption is usually false, NB is unreliable." Its classifications are often good despite the false assumption (sign preservation, §4.4); the probability calibration suffers first.
  3. "NB outputs proper probabilities." Its posteriors are typically over-confident (near 0/1). Use them for ranking/decisions, but calibrate before treating them as true probabilities.
  4. "You should always use $\alpha=1$." Laplace ($\alpha=1$) is a default; the best smoothing depends on vocabulary size and sparsity and should be cross-validated, especially for large sparse text.
  5. "Naive Bayes needs feature scaling / lots of data." It needs neither: it is invariant to affine rescaling (each feature is modelled separately) and data-efficient (low variance from few, simple parameters).
  6. "Multinomial and Bernoulli NB are interchangeable for text." They differ: Multinomial uses word counts and ignores absence; Bernoulli uses binary presence and explicitly models absence. They can give quite different results depending on document length and vocabulary.

26(s). Solutions

Level 1

  1. $P(x\mid y)=\prod_j P(x_j\mid y)$: features independent given the class. Needed because the full joint over $p$ (say binary) features has $2^p-1$ parameters per class (unestimable), while the factorisation needs only $p$ per class.
  2. Generative models model $P(x,y)$ (e.g. NB): they can generate data, marginalise missing features and need less data. Discriminative models model $P(y\mid x)$ (e.g. logistic regression): usually lower error with ample data and better calibrated.
  3. The classification is the sign of the summed log-odds; correlated features distort the magnitude (over-confidence) but usually keep the sign correct, so the argmax is right even when the probability is wrong.
  4. Long documents where a word appears many times: Multinomial (uses counts) rewards repetition; Bernoulli (presence only) treats one occurrence like many and also credits absence. For short texts / presence-driven tasks Bernoulli can win; for count-rich text prefer Multinomial.
  5. NB models each feature's distribution separately, so an affine rescaling of a feature only rescales its parameters and has no effect. KNN combines features into a single distance, so scale changes which points are nearest and thus the prediction.

Level 2

  1. $P(c\mid x)=\pi_c P(x\mid c)/P(x)$; drop $P(x)$ (constant across $c$, doesn't affect argmax) and factor $P(x\mid c)=\prod_j P(x_j\mid c)$ (independence) → $\hat y=\arg\max_c\pi_c\prod_jP(x_j\mid c)$.
  2. Prior: maximise $\sum_c N_c\log\pi_c$ s.t. $\sum\pi_c=1$; Lagrange gives $\hat\pi_c=N_c/N$. Gaussian mean: maximise $-\sum_i(x_i-\mu)^2/(2\sigma^2)$; setting derivative to 0 gives $\hat\mu=\frac1{N_c}\sum x_i$.
  3. $\log\frac{P(1\mid x)}{P(0\mid x)}=\log\frac{\pi_1}{\pi_0}+\sum_j\big[-\tfrac12\log\frac{\sigma_{1j}^2}{\sigma_{0j}^2}-\frac{(x_j-\mu_{1j})^2}{2\sigma_{1j}^2}+\frac{(x_j-\mu_{0j})^2}{2\sigma_{0j}^2}\big]$. If $\sigma_{1j}=\sigma_{0j}$ the quadratic $x_j^2$ terms cancel, leaving a linear function of $x$ (linear boundary); unequal variances leave $x_j^2$ terms → quadratic boundary.
  4. With a Dirichlet($\alpha$) prior and multinomial counts $N_{cj}$, the posterior is Dirichlet($N_{cj}+\alpha$); its mean for component $j$ is $(N_{cj}+\alpha)/\sum_j(N_{cj}+\alpha)=(N_{cj}+\alpha)/(N_c+\alpha K)$, the smoothing formula.
  5. Observation free=1, meeting=1. Likelihoods: spam $=0.75\times0.25=0.1875$; ham $=0.20\times0.70=0.140$. Posteriors $\propto$ spam $0.4286\times0.1875=0.0804$, ham $0.5714\times0.140=0.0800$ → $P(\text{spam})=0.0804/0.1604\approx0.501$, close to a toss-up, because "free" (spammy) and "meeting" (hammy) provide opposing evidence that nearly cancels.

Level 3

  1. Expected outcome: a log-space MNB (accumulate class-feature count sums, add $\alpha$, normalise to $\theta_{cj}$, score $\sum_j x_j\log\theta_{cj}+\log\pi_c$) should reproduce scikit-learn's predictions up to floating point when the same $\alpha$ and priors are used.
  2. Expected pattern: on count-vectorised text, Multinomial should beat Bernoulli on longer documents (counts matter) and Gaussian (the wrong likelihood for counts) should do worst; Bernoulli can be competitive on short texts. Report the measured figures.
  3. Expected pattern: the raw reliability curve shows over-confidence (below the diagonal at the high end, above at the low end); isotonic calibration should pull it towards the diagonal and lower log-loss and Brier score. Quantify both before and after.
  4. Expected pattern: NB has lower error at small $n$ and a flatter curve; logistic regression starts worse but keeps improving and crosses below NB as $n$ grows. Where the crossover falls depends on the data.
  5. Expected pattern: very small $\alpha$ gives extreme probabilities and possibly unstable accuracy; increasing $\alpha$ tempers the probabilities and stabilises accuracy up to a point, after which smoothing washes out signal and accuracy falls.
