Lecture 2: Logistic Regression

Part I: Mathematical Foundations and Classical Supervised Learning
Dr. Muhammad Shoaib · Applied Mathematics & Data Science · LinkedIn newsletter · every lecture follows the same 27 sections — use the sidebar to navigate.

In Lecture 1 we built the linear predictor $\eta = x^\top\beta$ and fitted it to a continuous target. Logistic regression keeps the same linear predictor, but the target is now a class label: spam or not, defaulted or not, malignant or benign. A linear function ranges over all of $\mathbb{R}$, whereas a probability must lie in $[0,1]$, and logistic regression resolves the mismatch by modelling the log-odds, which are unbounded. It is the standard classifier of applied statistics and the usual baseline for more flexible classifiers. For this course it matters for a further reason: it is a single-neuron neural network with a sigmoid activation and a cross-entropy loss. Understanding it fully means meeting, in miniature, the machinery of deep learning: the sigmoid, the log-loss, the gradient and gradient descent.

1. Motivation and Problem Setting

The problem. We observe feature vectors $x_i \in \mathbb{R}^p$ and a binary label $y_i \in \{0,1\}$. We want to model $P(y=1 \mid x)$, the probability of the positive class given the features, so that we can (a) rank examples by risk, (b) produce calibrated probabilities, and (c) draw a decision boundary to classify.

Why least squares on 0/1 labels fails. If you regress $y \in \{0,1\}$ on $x$ with OLS (the "linear probability model"), three things go wrong:

  • The fitted values are unbounded, so you get "probabilities" like $1.3$ or $-0.2$, which are meaningless.
  • The errors are inherently heteroscedastic: for a Bernoulli outcome the variance is $p(1-p)$, which depends on $x$, violating OLS's constant-variance assumption and invalidating its inference.
  • The linear form forces the effect of $x$ on probability to be constant everywhere, whereas near-certain regions ($p\approx0$ or $p\approx1$) should be insensitive to further change.

Logistic regression fixes all three by modelling the log-odds as linear, which automatically squashes predictions into $(0,1)$.

Why it was developed. The logistic function arose in 19th-century population growth models (Verhulst) and was adapted for binary regression in the mid-20th century (Berkson coined "logit"). It became dominant because it is the maximum-likelihood classifier under a simple probabilistic model and because its coefficients have a direct interpretation as log-odds ratios, which are standard in epidemiology, credit scoring, and the social sciences.

Where it sits. Logistic regression is a supervised, parametric, probabilistic and discriminative linear classifier: it outputs class probabilities, from which labels follow by thresholding. It is a generalised linear model (GLM) with a Bernoulli response and a logit link, the sibling of linear regression (Gaussian response, identity link) and Poisson regression (count response, log link). It is also a neural network with a single layer and a single output unit.

Assumptions.

  1. Linearity of the log-odds: $\log\frac{P(y=1\mid x)}{P(y=0\mid x)} = \beta_0 + \sum_j\beta_j x_j$. This is the core structural assumption: linearity in the log-odds, not in the probability.
  2. Independent observations (conditional on $x$).
  3. No perfect multicollinearity among features (else coefficients are unidentifiable).
  4. No perfect separation: if a hyperplane perfectly splits the classes, the MLE diverges (coefficients $\to\infty$). See §18.
  5. Large enough sample relative to the number of features (rule of thumb: at least ~10 events per predictor for stable estimates).

When reasonable / unreasonable. The log-odds-linear assumption is reasonable for many real problems and can be extended with engineered features (interactions, splines, polynomials) exactly as in linear regression. It is unreasonable when the decision boundary is curved or otherwise complex and you don't engineer features for it; then trees or kernel methods win. Perfect or near-perfect separation (common in small or high-dimensional data) breaks plain MLE and requires regularisation.

2. Core Intuition

Start with the odds. If an event has probability $p$, its odds are $\frac{p}{1-p}$, the ratio of "how likely it happens" to "how likely it doesn't." A probability of $0.8$ is odds of $4$ (four-to-one on). Odds range over $(0,\infty)$. Take the logarithm and you get the log-odds (the "logit"), which ranges over all of $(-\infty,\infty)$, exactly the range of a linear function. That is the key insight:

$$ \underbrace{\log\frac{p}{1-p}}_{\text{unbounded}} = \underbrace{\beta_0 + \beta_1 x_1 + \cdots + \beta_p x_p}_{\text{linear predictor}}. $$

Model the log-odds as linear (both sides are unbounded, so the ranges match), then invert to recover the probability. Solving the box for $p$ gives the sigmoid (logistic) function:

$$ p = \sigma(\eta) = \frac{1}{1+e^{-\eta}}, \qquad \eta = x^\top\beta. $$

Geometric intuition. The sigmoid is an S-shaped curve that maps the whole real line into $(0,1)$: at $\eta=0$ it passes through $0.5$; as $\eta\to+\infty$ it saturates at $1$; as $\eta\to-\infty$ at $0$. The linear predictor $\eta = x^\top\beta$ defines a hyperplane; the sigmoid then "wraps" that flat plane into a smooth probability surface that is steepest at the boundary and flattens into near-certainty far from it. The set where $\eta=0$ (i.e. $p=0.5$) is the decision boundary, and it is a hyperplane, so logistic regression is a linear classifier.

Probabilistic intuition. Each label is a coin flip whose bias depends on $x$: $y \sim \text{Bernoulli}(\sigma(x^\top\beta))$. Fitting means choosing $\beta$ to make the observed sequence of heads/tails (1s/0s) as probable as possible, which is maximum likelihood. Because we are fitting probabilities, we penalise confident-but-wrong predictions harshly (predicting $p=0.99$ when the truth is $y=0$ costs a lot), which is what the log-loss encodes.

Optimisation intuition. Unlike linear regression, there is no closed form, but the negative log-likelihood is convex, so there is a single global optimum and gradient-based methods find it reliably.

Tiny numerical seed. One feature, hours studied $x$, pass/fail $y$. If $\hat\beta_0=-4,\hat\beta_1=1.5$, then a student with $x=3$ has $\eta=-4+4.5=0.5$, so $p=\sigma(0.5)\approx0.62$: predicted to pass, but not confidently.

3. Mathematical Formulation

Notation. As in Lecture 1, prepend a $1$ to each feature vector so $x_i=(1,x_{i1},\dots,x_{ip})^\top\in\mathbb{R}^{p+1}$ and $\beta=(\beta_0,\dots,\beta_p)^\top$. Labels $y_i\in\{0,1\}$. Write the linear predictor $\eta_i = x_i^\top\beta$ and the predicted probability $p_i = \sigma(\eta_i)$.

The sigmoid and its properties.

$$ \sigma(z) = \frac{1}{1+e^{-z}}, \qquad \sigma(-z)=1-\sigma(z), \qquad \sigma'(z)=\sigma(z)\big(1-\sigma(z)\big). $$

That last identity, $\sigma' = \sigma(1-\sigma)$, is what makes the gradients so clean, and we will use it repeatedly.

The model.

$$ P(y=1\mid x)=\sigma(x^\top\beta)=\frac{1}{1+e^{-x^\top\beta}}, \qquad P(y=0\mid x)=1-\sigma(x^\top\beta). $$

Compactly, for $y\in\{0,1\}$: $\;P(y\mid x)=p^{\,y}(1-p)^{1-y}$ (the Bernoulli pmf).

The likelihood. Assuming independent observations,

$$ L(\beta)=\prod_{i=1}^n p_i^{\,y_i}(1-p_i)^{1-y_i}. $$

The log-likelihood. Products become sums under the log:

$$ \ell(\beta)=\sum_{i=1}^n\Big[\,y_i\log p_i+(1-y_i)\log(1-p_i)\,\Big]. $$

The loss (objective). We minimise the negative log-likelihood, which is the binary cross-entropy:

$$ J(\beta)=-\frac{1}{n}\sum_{i=1}^n\Big[\,y_i\log p_i+(1-y_i)\log(1-p_i)\,\Big], \qquad p_i=\sigma(x_i^\top\beta). $$

Cross-entropy and negative log-likelihood are the same object here, so "log-loss", "cross-entropy" and "maximum likelihood" name the same procedure.

Regularised variants. Add a penalty on the weights (never the intercept):

$$ J_{\ell_2}(\beta)=J(\beta)+\frac{\lambda}{2}\|\beta_{1:p}\|_2^2, \qquad J_{\ell_1}(\beta)=J(\beta)+\lambda\|\beta_{1:p}\|_1. $$

$\ell_2$ (ridge-style) shrinks coefficients and tames separation; $\ell_1$ (lasso-style) yields sparse, feature-selecting solutions.

4. Derivation

4.1 From odds to the sigmoid

Assume the log-odds are linear: $\log\frac{p}{1-p}=\eta$ where $\eta=x^\top\beta$. Exponentiate: $\frac{p}{1-p}=e^{\eta}$. Solve for $p$:

$$ p=e^{\eta}(1-p)\ \Rightarrow\ p+pe^{\eta}=e^{\eta}\ \Rightarrow\ p=\frac{e^{\eta}}{1+e^{\eta}}=\frac{1}{1+e^{-\eta}}=\sigma(\eta). $$

So "log-odds linear" is equivalent to "probability = sigmoid of a linear predictor." The sigmoid is the inverse of the logit link, so it follows from the log-odds assumption.

4.2 The cross-entropy loss from maximum likelihood

Take the log of the Bernoulli likelihood:

$$ \ell(\beta)=\log\prod_i p_i^{y_i}(1-p_i)^{1-y_i}=\sum_i\big[y_i\log p_i+(1-y_i)\log(1-p_i)\big]. $$

Maximising $\ell$ is minimising $-\ell$, the cross-entropy. The reason this loss punishes confident errors: if $y_i=1$ but $p_i\to0$, then $\log p_i\to-\infty$, an unboundedly large penalty. Cross-entropy is also a proper scoring rule: its expected value is minimised by reporting the true probability.

4.3 The gradient (score function)

This is the derivation to know cold. We need $\nabla_\beta\ell$. Work on one term and use the chain rule through $p_i=\sigma(\eta_i)$, $\eta_i=x_i^\top\beta$.

First, the derivative of a single log-likelihood term with respect to $p_i$:

$$ \frac{\partial}{\partial p_i}\big[y_i\log p_i+(1-y_i)\log(1-p_i)\big]=\frac{y_i}{p_i}-\frac{1-y_i}{1-p_i}=\frac{y_i-p_i}{p_i(1-p_i)}. $$

Next, $\frac{\partial p_i}{\partial\eta_i}=\sigma'(\eta_i)=p_i(1-p_i)$, and $\frac{\partial\eta_i}{\partial\beta}=x_i$. Multiplying the chain together, the $p_i(1-p_i)$ factors cancel:

$$ \frac{\partial\ell_i}{\partial\beta}=\frac{y_i-p_i}{p_i(1-p_i)}\cdot p_i(1-p_i)\cdot x_i=(y_i-p_i)\,x_i. $$

Summing over observations gives the full gradient of the log-likelihood, and hence of the loss $J=-\frac1n\ell$:

$$ \nabla_\beta\ell=\sum_{i=1}^n(y_i-p_i)\,x_i = X^\top(y-p), \qquad \nabla_\beta J=-\frac1n X^\top(y-p). $$

Read it: the gradient is the feature matrix times the residual $(y_i-p_i)$, the difference between observed label and predicted probability. This has the same form as the linear-regression gradient $X^\top(y-\hat y)$; only the meaning of the prediction changed (a probability instead of a real value). This is why a logistic output unit fits directly into a neural network: backpropagation through it needs only $(y-p)$.

4.4 The Hessian and convexity

Differentiate the gradient again. Since $\frac{\partial p_i}{\partial\beta}=p_i(1-p_i)x_i$,

$$ \nabla^2_\beta\ell=-\sum_{i=1}^n p_i(1-p_i)\,x_i x_i^\top = -X^\top S X, \qquad S=\operatorname{diag}\big(p_i(1-p_i)\big). $$

Each $p_i(1-p_i)>0$, so $X^\top S X$ is positive semidefinite, meaning the negative log-likelihood $J$ has a positive-semidefinite Hessian, so it is convex. Convexity guarantees no spurious local minima: any optimiser that reaches a stationary point has found the global optimum. (With $\ell_2$ regularisation the Hessian becomes $X^\top SX+\lambda I\succ0$, strictly convex, so the optimum is unique even under separation.)

4.5 Newton's method / IRLS

A Newton step uses both gradient and Hessian:

$$ \beta^{(t+1)}=\beta^{(t)}+(X^\top S X)^{-1}X^\top(y-p). $$

Rearranged, each iteration is a weighted least-squares solve, hence the name iteratively reweighted least squares (IRLS). Each iteration re-linearises the problem and solves a weighted OLS with weights $p_i(1-p_i)$ (largest near $p=0.5$, where an observation is most informative). Each step therefore solves weighted versions of the normal equations from Lecture 1.

5. Algorithm

Gradient descent version (scales to large data):

Input: X (n×(p+1), first col ones), y ∈ {0,1}^n, learning rate η, iters T, (optional) λ
1. Initialise β ← 0            # zero is fine; loss is convex
2. repeat T times (or until ||gradient|| < tol):
     η_vec = X β               # linear predictor, shape (n,)
     p     = 1 / (1 + exp(−η_vec))     # predicted probabilities
     grad  = (1/n) Xᵀ (p − y) + λ·[0, β₁..β_p]   # ∇J (intercept unpenalised)
     β     = β − η · grad      # descend
3. return β
Predict: p* = σ(x*ᵀβ);  label = 1 if p* ≥ threshold (default 0.5) else 0

Newton / IRLS version (fast on small–medium p, few iterations):

1. Initialise β ← 0
2. repeat until convergence:
     p = σ(Xβ);  S = diag(p_i(1−p_i))
     β ← β + (Xᵀ S X + λI)⁻¹ Xᵀ (y − p)     # one weighted-least-squares solve
3. return β, and Cov(β) ≈ (Xᵀ S X)⁻¹  for standard errors

Stopping criteria: gradient norm below tolerance, change in loss below tolerance, or a max-iteration cap. Outputs: the coefficient vector $\hat\beta$; predicted probabilities; optionally the covariance of $\hat\beta$ (from the inverse Hessian) for inference.

We'll take a fixed candidate $\beta=(\beta_0,\beta_1)=(-5,\,2)$ and compute one gradient step by hand to show the mechanics (the true MLE is found by iterating this).

Step 1: linear predictors $\eta_i=\beta_0+\beta_1 x_i$:

$$ \eta_1=-5+2=-3,\quad \eta_2=-5+4=-1,\quad \eta_3=-5+6=1,\quad \eta_4=-5+8=3. $$

Step 2: probabilities $p_i=\sigma(\eta_i)$:

$$ p_1=\sigma(-3)\approx0.0474,\ \ p_2=\sigma(-1)\approx0.2689,\ \ p_3=\sigma(1)\approx0.7311,\ \ p_4=\sigma(3)\approx0.9526. $$

Step 3: residuals $y_i-p_i$:

$$ 0-0.0474=-0.0474,\quad 0-0.2689=-0.2689,\quad 1-0.7311=0.2689,\quad 1-0.9526=0.0474. $$

Step 4: gradient of log-likelihood $\nabla\ell=\sum_i(y_i-p_i)x_i$ (components: intercept uses $x_{i0}=1$, slope uses $x_i$):

$$ \frac{\partial\ell}{\partial\beta_0}=\sum_i(y_i-p_i)=-0.0474-0.2689+0.2689+0.0474=0. $$ $$ \frac{\partial\ell}{\partial\beta_1}=\sum_i(y_i-p_i)x_i=(-0.0474)(1)+(-0.2689)(2)+(0.2689)(3)+(0.0474)(4) $$ $$ =-0.0474-0.5378+0.8067+0.1896=0.4111. $$

The intercept gradient is exactly $0$ here because this symmetric dataset already balances the classes at $\beta_0=-5,\beta_1=2$ (the data are symmetric about $x=2.5$ and this line puts $p=0.5$ there). The slope gradient is positive, so gradient ascent on $\ell$ (descent on $J$) would increase $\beta_1$: the model wants a steeper slope, sharpening the boundary. This is consistent with the data being perfectly separable, which drives $\beta_1\to\infty$ at the unregularised MLE (see §18).

Step 5: current loss (cross-entropy). Per-observation $-[y\log p+(1-y)\log(1-p)]$:

$$ -\log(1-p_1)=-\log0.9526=0.0486,\quad -\log(1-p_2)=-\log0.7311=0.3133, $$ $$ -\log p_3=-\log0.7311=0.3133,\quad -\log p_4=-\log0.9526=0.0486. $$

Average $J=(0.0486+0.3133+0.3133+0.0486)/4\approx0.181$. Increasing $\beta_1$ (steeper boundary) would push $p_3,p_4$ towards $1$ and $p_1,p_2$ towards $0$, lowering $J$ further towards $0$, again the separation signature.

7. Geometry and Visual Interpretation

The decision boundary is a hyperplane. We classify as positive when $p\ge0.5$, i.e. when $\sigma(x^\top\beta)\ge0.5$, i.e. when $x^\top\beta\ge0$. The set $\{x:x^\top\beta=0\}$ is a flat hyperplane in feature space; $\beta_{1:p}$ is its normal vector, pointing in the direction of increasing probability. So despite the nonlinear sigmoid, the boundary is linear, and logistic regression is a linear classifier. A useful picture: a 2D scatter of two classes, a straight dividing line, and shaded contours of constant probability ($0.1,0.3,0.5,0.7,0.9$) running parallel to that line, packed tightly where the sigmoid is steep and spreading out towards the saturated corners.

The probability surface. Over 2D feature space, $p(x)=\sigma(x^\top\beta)$ is a smooth "ramp": flat near $0$ on one side, flat near $1$ on the other, with a diagonal S-shaped rise across the boundary. The steepness of the ramp is governed by $\|\beta\|$: larger weights → sharper transition (more confident, more like a step function); smaller weights → gentle, uncertain slope. Regularisation shrinks $\|\beta\|$ and thus softens the ramp.

Curved boundaries via features. Just as polynomial linear regression fits curves, adding $x_1^2, x_2^2, x_1x_2$ etc. to logistic regression produces boundaries that are ellipses, parabolas, or more complex shapes in the original feature space, while remaining a hyperplane in the expanded feature space. The linearity is in the (possibly transformed) features.

8. Statistical Interpretation

Coefficients are log-odds ratios. A one-unit increase in $x_j$ (holding others fixed) adds $\beta_j$ to the log-odds, i.e. multiplies the odds by $e^{\beta_j}$. So $e^{\beta_j}$ is the odds ratio. Example: $\beta_j=0.7\Rightarrow e^{0.7}\approx2.0$, meaning each unit of $x_j$ doubles the odds. Odds ratios also remain estimable under case–control sampling, where only the intercept is distorted, which is one reason the model is standard in epidemiology.

MLE properties. The maximum-likelihood estimator $\hat\beta$ is consistent and asymptotically normal: $\hat\beta \approx \mathcal{N}\big(\beta,\,(X^\top S X)^{-1}\big)$ for large $n$, where $X^\top S X$ is the observed Fisher information (the negative Hessian). Standard errors are the square roots of the diagonal of $(X^\top S X)^{-1}$. Unlike OLS, these results are asymptotic (large-sample), not exact.

Inference. The Wald test uses $z_j=\hat\beta_j/\operatorname{SE}(\hat\beta_j)$ compared to a standard normal; a confidence interval for the odds ratio is $\exp\big(\hat\beta_j\pm z_{1-\alpha/2}\operatorname{SE}(\hat\beta_j)\big)$. The likelihood-ratio test compares $2(\ell_{\text{full}}-\ell_{\text{reduced}})$ to a $\chi^2$ distribution and is generally more reliable than Wald (especially near separation). Model fit is often summarised by the deviance $=-2\ell$, analogous to RSS.

ML vs inference framing. The statistician reads off odds ratios, Wald/LR tests, and confidence intervals to make claims about associations. The machine learner cares about held-out log-loss, AUC, and calibration. Same fitted model; the caution from Lecture 1 applies doubly: $p$-values are invalid if you data-snooped the feature set, and asymptotic SEs are unreliable in small or separated data.

9. Training and Optimisation

No closed form. Setting $\nabla\ell=X^\top(y-p)=0$ gives $p$ as a nonlinear function of $\beta$ through the sigmoid, so there is no algebraic solution, and we must optimise numerically. What keeps this tractable is convexity (§4.4): the loss surface is a single bowl, so any convergent descent method reaches the global optimum.

  • Gradient descent / SGD: update $\beta\leftarrow\beta-\eta\,\frac1n X^\top(p-y)$. Simple, scales to millions of rows, the same optimiser used for neural nets. Standardise features so a single learning rate suits all coordinates.
  • Newton's method / IRLS: uses the Hessian for quadratic convergence, typically 5–10 iterations to high precision on small/medium problems. Cost per iteration is a $p\times p$ solve ($O(np^2+p^3)$), so it's preferred when $p$ is modest. This is what statsmodels uses by default and it returns the Fisher-information covariance as a by-product.
  • Quasi-Newton (L-BFGS): approximates the Hessian without forming it; scikit-learn's default solver. A good middle ground for medium/large $p$.
  • Coordinate descent: the method of choice for $\ell_1$-penalised logistic regression (the liblinear solver), because the non-smooth $\ell_1$ term can be handled one coordinate at a time. The saga solver also supports $\ell_1$, using proximal stochastic-gradient steps.

Convergence caveat: separation. If the data are linearly separable, the likelihood has no finite maximiser: pushing $\|\beta\|\to\infty$ keeps increasing the likelihood towards 1. Iterative solvers then fail to converge (coefficients and SEs blow up). Fixes: $\ell_2$ regularisation (restores a finite unique optimum), or Firth's penalised likelihood.

10. Hyperparameters

$C$ (inverse regularisation strength): scikit-learn's main knob; $C=1/\lambda$.

  • Mathematically: the objective is $\;J(\beta)+\frac{1}{C}\cdot\text{penalty}$ (or equivalently $C\cdot\text{loss}+\text{penalty}$ depending on convention). Large $C$ = weak penalty; small $C$ = strong penalty.
  • Increasing $C$ (weaker regularisation): coefficients grow, boundary sharpens → lower bias, higher variance; risks overfitting and separation blow-up.
  • Decreasing $C$ (stronger regularisation): coefficients shrink towards 0, boundary softens → higher bias, lower variance; at $C\to0$ the model predicts the base rate everywhere.
  • Cost: negligible per-fit; the cost is the CV search. Guidance: tune on a log grid ($10^{-3}$ to $10^{3}$) by cross-validated log-loss or AUC; always standardise features first.

Penalty type: $\ell_2$, $\ell_1$ or elastic net. $\ell_2$ shrinks smoothly and stabilises separation (default choice); $\ell_1$ drives coefficients to exactly zero for feature selection; elastic net blends both. In scikit-learn 1.8 the type is set by l1_ratio (0 for $\ell_2$, 1 for $\ell_1$, values in between for elastic net); the older penalty argument is deprecated. Choice controls the shape of the constraint region, with the same geometry as Lecture 1 §19.

Decision threshold. A deployment choice, separate from training: the $0.5$ cut is arbitrary. Lowering the threshold raises recall at the cost of precision (and vice versa). Choose it from the business cost of false positives vs false negatives, or to hit a target on the ROC/PR curve, once the model is fitted.

Class weights. class_weight='balanced' reweights the loss by inverse class frequency, effectively up-weighting the minority class, which matters under imbalance (§13).

Solver and max_iter. Numerical, not statistical: pick a solver compatible with your penalty (lbfgs/newton-cg for $\ell_2$, liblinear/saga for $\ell_1$), and raise max_iter if you see convergence warnings.

11. Bias–Variance Behaviour

  • Underfitting (high bias): the true boundary is nonlinear but you fit only a plain linear logit, or you regularise too hard (small $C$). The model cannot bend to the data; both train and test error stay high. Remedy: add interaction/polynomial/spline features, or increase $C$.
  • Overfitting (high variance): many features relative to $n$, high-degree engineered features, or weak regularisation (large $C$). Coefficients grow large, the boundary contorts around training points, and, in the extreme, the data become separable and coefficients diverge. Symptoms: near-perfect training performance, poor test log-loss and implausibly large coefficients. Remedy: stronger regularisation, fewer features, more data.
  • Model capacity is set jointly by the feature richness and $\|\beta\|$; regularisation is the dial that trades a little bias for a large reduction in variance, usually improving held-out log-loss.
  • Data-size sensitivity: logistic regression is data-efficient: with $p$ small it needs relatively few events to estimate stable coefficients (the "10 events per predictor" heuristic). Small samples inflate variance and make separation likely, so regularise.

12. Computational Complexity

Let $n$ = observations, $p$ = features, $T$ = iterations.

  • Training (gradient descent / L-BFGS): each iteration computes $Xβ$ and $X^\top(p-y)$, both $O(np)$; total $O(npT)$. Scales linearly in both $n$ and $p$, which suits large, wide data.
  • Training (Newton/IRLS): $O(np^2+p^3)$ per iteration (form and solve the weighted normal equations), few iterations. Suitable when $p$ is small or moderate; the $p^3$ term dominates for large $p$.
  • Prediction: $O(p)$ per example: one dot product and a sigmoid. Cheap enough for low-latency serving.
  • Memory: $O(np)$ for the data; $O(p)$ for the model. Newton adds $O(p^2)$ for the Hessian.

Scalability: among the most scalable classifiers. For large $n$, SGD or the saga solver streams through data; for huge $p$, prefer first-order/coordinate methods over Newton.

13. Data Preparation

  • Feature scaling: not required for correctness of unregularised logistic regression (rescaling a feature just rescales its coefficient), but required when you regularise (the penalty is scale-sensitive) and strongly recommended for gradient/L-BFGS convergence. Standardise (zero mean, unit variance) by default.
  • Categorical variables: one-hot encode (drop one level to avoid collinearity with the intercept). High-cardinality categoricals may need target/frequency encoding or a different model.
  • Nonlinearity: add polynomial terms, splines, or interactions to capture curved boundaries; the model only sees the features you give it.
  • Missing values: impute (and consider missingness indicators); logistic regression needs complete cases.
  • Outliers: far less catastrophic than in OLS because the sigmoid saturates: an extreme $x$ pins $p$ near 0 or 1, whereas in a squared-error fit it would pull the line towards itself. Still worth checking, as extreme values can influence the boundary.
  • Class imbalance: with a rare positive class, use class_weight='balanced', resampling (SMOTE/undersampling), or, often best, leave the probabilities alone and move the decision threshold. Accuracy is meaningless under heavy imbalance (§14).
  • Multicollinearity: inflates coefficient variance and destabilises signs (as in OLS); check VIFs and regularise or drop redundant features.

14. Evaluation

Logistic regression outputs probabilities, so evaluate both the ranking/classification and the probability quality.

  • Accuracy: fraction correct at a chosen threshold. Misleading under imbalance: predicting "all negative" scores 99% accuracy if positives are 1%.
  • Precision, recall, F1: precision $=\frac{TP}{TP+FP}$ (of predicted positives, how many are right), recall $=\frac{TP}{TP+FN}$ (of actual positives, how many caught), F1 their harmonic mean. Report these under imbalance and choose by the cost trade-off.
  • ROC-AUC: probability a random positive is ranked above a random negative; threshold-independent measure of ranking. Can look optimistic under heavy imbalance.
  • PR-AUC: area under precision–recall; more informative than ROC-AUC when positives are rare.
  • Log-loss (cross-entropy): the model's own training objective; rewards calibrated, confident-and-correct probabilities and punishes confident errors. The most faithful single number for a probabilistic classifier.
  • Brier score: mean squared error of the predicted probabilities, a proper scoring rule complementary to log-loss.
  • Calibration: agreement between predicted probabilities and observed frequencies, assessed with a reliability diagram (§16). Logistic regression tends to be well calibrated: with an intercept, the score equations $X^\top(y-p)=0$ force the mean predicted probability to equal the observed positive rate, and the same balance holds along each feature. SVM scores and naive Bayes probabilities have no such property.

Why metrics mislead: a high accuracy hides poor minority-class recall; a high ROC-AUC can coexist with badly miscalibrated probabilities; a good threshold on the training set may be wrong on new data. Match the metric to the decision the model will drive.

15. Validation Strategy

  • Stratified $k$-fold cross-validation: the default; stratification preserves the class ratio in each fold, essential when positives are scarce.
  • Train/validation/test split for large data; keep a final untouched test set for the honest estimate.
  • Nested CV when tuning $C$/penalty and reporting generalisation, to avoid optimistic bias from selecting on the same data.
  • Grouped CV when rows cluster (multiple records per customer/patient): keep groups intact.
  • Time-aware validation for temporal data (e.g. credit default): train on past, validate on future; never shuffle across time.

Leakage risks: fit scaling, imputation, encoding, and feature selection inside each fold via a Pipeline. A subtle one specific to classification: choosing the decision threshold or calibrating probabilities on the test set. Do it on validation data only.

16. Diagnostics

  • Calibration / reliability plot: bin predictions by predicted probability, plot observed frequency vs mean predicted probability; the diagonal is perfect calibration. Systematic deviation signals miscalibration (over/under-confidence).
  • Confusion matrix at the operating threshold: reveals whether errors are false positives or false negatives.
  • ROC and PR curves: visualise the full threshold trade-off and choose the operating point.
  • Coefficient table with SEs / odds ratios and CIs: for interpretation and sanity checks (implausible signs suggest collinearity or leakage).
  • Deviance residuals: the logistic analogue of OLS residuals; patterns against a feature indicate missing nonlinearity.
  • Separation check: huge coefficients with huge SEs, or a non-converging solver, flag (quasi-)perfect separation.
  • Learning curves: train vs validation log-loss against $n$ to distinguish bias from variance.
  • VIF / correlation matrix: detect multicollinearity.
  • Feature effects: partial dependence, or plotting $\sigma(x^\top\beta)$ against a feature to communicate its influence.

17. Strengths

  • Well-calibrated probabilities. Because it maximises the Bernoulli likelihood, its outputs can be used directly as probabilities for ranking, thresholding and expected-value decisions; raw SVM scores cannot.
  • Interpretability. $e^{\beta_j}$ is an odds ratio: an interpretable effect size with a confidence interval.
  • Convex objective. A single global optimum, reliably found; results are reproducible and stable, with no initialisation lottery.
  • Cheap and scalable. $O(np)$ per gradient step, $O(p)$ prediction; trains on huge data and serves at low latency.
  • Statistical inference available. Wald/LR tests, SEs, and CIs via Fisher information; few ML classifiers offer this.
  • Naturally regularisable. $\ell_1/\ell_2$ slot in cleanly, giving feature selection and separation control with the same convex machinery.
  • Strong, honest baseline. Hard to beat on linearly-structured tabular data; if a complex model can't beat it, that's informative.

18. Weaknesses and Failure Modes

  • Linear decision boundary only. Without engineered features it cannot capture curved or interaction-driven boundaries. Example: the XOR pattern (positives in opposite quadrants) is unclassifiable by a plain logit; you must add an $x_1x_2$ term.
  • Perfect separation blows up the MLE. If a feature (or combination) perfectly predicts the class, coefficients diverge to $\pm\infty$, SEs explode, and the solver fails. Example: a rare disease where every positive has a unique symptom absent in negatives. Fix: $\ell_2$ penalty or Firth's correction.
  • High-dimensional / small-$n$ instability. When $p$ approaches $n$, unregularised estimates have very high variance; regularisation is necessary.
  • Multicollinearity. Correlated predictors give unstable, uninterpretable coefficients (signs can flip) though predictions may still be fine.
  • Sensitive to feature misspecification. If the true log-odds are nonlinear in a feature and you model it as linear, the fit is biased and calibration suffers.
  • Class imbalance. With rare positives the intercept dominates and the model predicts near-base-rate; needs class weighting/resampling and threshold tuning, and accuracy becomes uninformative.
  • Independence assumption. Correlated observations (clustered/temporal) make the naive SEs too small, so inference is over-confident.
  • Extrapolation. Like all linear models, predictions far outside the training range assume the log-odds trend continues, which may be false.

vs Linear Regression: same linear predictor $x^\top\beta$; logistic wraps it in a sigmoid and swaps the Gaussian likelihood for Bernoulli. Never use OLS on 0/1 labels (unbounded, heteroscedastic).

vs Linear SVM: both are linear discriminative classifiers with convex objectives. Logistic uses log-loss (every point contributes, probabilities are calibrated); SVM uses hinge loss (only margin-violating support vectors matter, outputs are uncalibrated scores). Logistic is preferred when you need probabilities; SVM can be more robust to outliers far from the boundary and pairs naturally with kernels for nonlinearity. Their fitted boundaries are often similar on nearly separable data.

vs Naive Bayes / LDA (generative): logistic is discriminative: it models $P(y\mid x)$ directly, making fewer assumptions about the feature distribution, and generally wins with enough data. Generative models (coming in Week 4) can win in the small-data regime because they borrow strength from stronger distributional assumptions. Ng and Jordan (2002) analysed this pair: with variances shared across classes, Gaussian naive Bayes and logistic regression have the same functional form for $P(y\mid x)$ but estimate its parameters differently. Naive Bayes approaches its asymptotic error with fewer observations, but logistic regression's asymptotic error is lower, so it tends to win once data are plentiful.

vs Trees / GBMs / Neural nets: those capture nonlinearity and interactions automatically at the cost of interpretability and, for neural networks, calibration and data requirements. Adding a hidden layer to logistic regression gives a neural network, in which the logistic unit is the basic building block.

20. When I Should Use It

Use logistic regression when:

  • You need probabilities as well as labels (risk scores, expected-value decisions).
  • You need interpretable effects (odds ratios) and possibly formal inference: regulated domains, science, medicine.
  • The decision boundary is plausibly linear in your (possibly engineered) features.
  • Data are limited, or you want a fast and reproducible baseline.
  • You need cheap, low-latency prediction at scale.
  • Class imbalance is manageable via weighting/threshold tuning.

Avoid (or augment) logistic regression when:

  • The boundary is strongly nonlinear with unknown form and you can't feature-engineer it → trees, GBMs, kernels, or nets.
  • There are many high-order interactions you can't specify by hand.
  • Data are (quasi-)perfectly separable and you cannot/should not regularise (then estimates are unstable; at minimum add a penalty).
  • Features are extremely high-dimensional and sparse with complex structure (text/images) where specialised models excel, although regularised logistic regression remains a strong text baseline.

21. Python Implementation From Scratch

import numpy as np

def sigmoid(z):
    # Numerically stable sigmoid: avoid overflow in exp for large |z|.
    out = np.empty_like(z, dtype=float)
    pos = z >= 0
    out[pos]  = 1.0 / (1.0 + np.exp(-z[pos]))
    ez = np.exp(z[~pos])
    out[~pos] = ez / (1.0 + ez)
    return out

class LogisticRegressionScratch:
    """Binary logistic regression via gradient descent with optional L2."""

    def __init__(self, lr=0.1, n_iter=5000, l2=0.0, fit_intercept=True):
        self.lr = lr                # learning rate η
        self.n_iter = n_iter
        self.l2 = l2                # λ (0 = no regularisation)
        self.fit_intercept = fit_intercept
        self.beta_ = None

    def _design(self, X):
        if self.fit_intercept:
            return np.hstack([np.ones((X.shape[0], 1)), X])
        return X

    def fit(self, X, y):
        Xd = self._design(np.asarray(X, float))
        y  = np.asarray(y, float).ravel()
        n, k = Xd.shape
        self.beta_ = np.zeros(k)                       # convex ⇒ zero init is fine

        for _ in range(self.n_iter):
            p = sigmoid(Xd @ self.beta_)               # predicted probabilities
            # Gradient of the (mean) negative log-likelihood:  (1/n) Xᵀ(p − y)
            grad = Xd.T @ (p - y) / n
            if self.l2:                                # do not penalise intercept
                reg = self.l2 * self.beta_
                reg[0] = 0.0
                grad = grad + reg / n
            self.beta_ -= self.lr * grad               # descend the convex bowl
        return self

    def predict_proba(self, X):
        return sigmoid(self._design(np.asarray(X, float)) @ self.beta_)

    def predict(self, X, threshold=0.5):
        return (self.predict_proba(X) >= threshold).astype(int)

# --- demo on the worked example -----------------------------------
X = np.array([[1], [2], [3], [4]], float)
y = np.array([0, 0, 1, 1])

# With L2 the separable data yields finite coefficients; without it, β₁ grows large.
model = LogisticRegressionScratch(lr=0.5, n_iter=20000, l2=1.0).fit(X, y)
print("beta      :", model.beta_)
print("proba     :", model.predict_proba(X).round(3))
print("odds ratio:", np.exp(model.beta_[1]))    # e^{β₁}: multiplicative effect per hour

Correspondence to the maths.

  • sigmoid implements $\sigma(z)$ from §3, split by sign to avoid exp overflow (a real production concern).
  • Xd.T @ (p - y) / n is $\frac1n X^\top(p-y)$, the gradient derived in §4.3, the feature matrix times the residual.
  • The intercept is excluded from the penalty (reg[0]=0), matching the convention in §3.
  • np.exp(beta_[1]) converts a coefficient to an odds ratio (§8).

import numpy as np
import pandas as pd
from sklearn.compose import ColumnTransformer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler, OneHotEncoder
from sklearn.linear_model import LogisticRegression

When to use which: scikit-learn for prediction, pipelines, tuning, calibration, and deployment; statsmodels for the inferential coefficient table (odds ratios, Wald $z$, $p$-values, likelihood-ratio and pseudo-$R^2$). scikit-learn regularises by default ($\ell_2$ with $C=1$), which is why it does not report classical $p$-values: the standard asymptotic inference does not apply to the penalised estimate.

23. Library Parameters Mapped to Mathematics

sklearn.linear_model.LogisticRegression

  • C: inverse regularisation strength, $C=1/\lambda$. The objective is $C\sum_i \text{logloss}_i + \frac12\|\beta\|^2$ (for $\ell_2$). Large $C$ → weak penalty, larger coefficients, lower bias/higher variance (§10, §11); small $C$ → strong shrinkage. The single most important knob.
  • l1_ratio: the penalty type, which sets the shape of the constraint region. 0 gives $\ell_2$ (smooth shrinkage, stabilises separation; the default), 1 gives $\ell_1$ (sparsity and feature selection, the diamond geometry), and values in between give the elastic net. An unpenalised fit (pure MLE; beware separation) is C=np.inf. Before scikit-learn 1.8 these were set with penalty='l2', 'l1', 'elasticnet' or None; that argument is deprecated and will be removed in 1.10.
  • solver, the optimiser: 'lbfgs'/'newton-cg' (quasi-Newton and Newton methods, $\ell_2$ only), 'liblinear' (coordinate descent, good for $\ell_1$ and small data), 'saga' (stochastic, scales to large $n$, supports elastic-net). Purely numerical: same estimator, different route (and separation behaviour).
  • class_weight: reweights each class's contribution to the loss; 'balanced' uses inverse frequencies, effectively multiplying the minority class's log-loss terms so the gradient $X^\top(p-y)$ pays it more attention (§13).
  • fit_intercept: whether $\beta_0$ is included (the constant column); the intercept absorbs the base log-odds and is not penalised.
  • max_iter, tol: iteration cap and convergence tolerance for the iterative solver; raise max_iter on convergence warnings (often a sign of poor scaling or separation).
  • Multiclass problems: scikit-learn fits the multinomial (softmax cross-entropy) model directly. The multi_class argument that chose between one-vs-rest and multinomial was deprecated in 1.5 and is absent from 1.8; one-vs-rest remains available through OneVsRestClassifier.

statsmodels.Logit

  • .fit(method='newton'): IRLS/Newton (§4.5), returning the Fisher-information covariance for SEs.
  • .fit_regularized(alpha=..., L1_wt=...): penalised MLE; alpha is $\lambda$, L1_wt mixes $\ell_1$/$\ell_2$.
  • .params are log-odds coefficients; np.exp(.params) are odds ratios (§8).

24. Common Interview Questions

1. Why can't we use linear regression for binary classification?
Its outputs are unbounded (giving impossible probabilities outside $[0,1]$), the Bernoulli errors are heteroscedastic ($\operatorname{Var}=p(1-p)$) violating OLS assumptions, and it forces a constant marginal effect on probability. The logit link fixes all three by modelling log-odds linearly.

2. Derive the logistic-regression gradient and explain why its form matters.
$\nabla_\beta\ell=\sum_i(y_i-p_i)x_i=X^\top(y-p)$. The chain rule's $\sigma'=\,p(1-p)$ cancels the $1/[p(1-p)]$ from the log-likelihood derivative, leaving the clean "features times residual" form, identical in structure to OLS, which is why a logistic unit backprops trivially.

3. Is the logistic loss convex? Prove it and say why it matters.
The Hessian is $-X^\top S X$ with $S=\operatorname{diag}(p_i(1-p_i))\succeq0$, so the negative log-likelihood has PSD Hessian → convex. It matters because gradient methods reach the global optimum regardless of initialisation; there are no bad local minima.

4. Interpret a coefficient of $\beta_j=1.1$.
A one-unit increase in $x_j$ adds $1.1$ to the log-odds, multiplying the odds by $e^{1.1}\approx3.0$, roughly tripling the odds of the positive class, holding other features fixed. It does not mean the probability triples.

5. What is perfect separation and how do you handle it?
When a hyperplane perfectly splits the classes, the likelihood increases without bound as $\|\beta\|\to\infty$; there is no finite MLE, so solvers diverge and SEs explode. Fix with $\ell_2$ regularisation (restores a unique finite optimum) or Firth's penalised likelihood.

6. Logistic regression vs linear SVM: when do you prefer each?
Prefer logistic when you need calibrated probabilities or interpretable odds ratios (log-loss uses all points). Prefer SVM (hinge loss) when you only need the boundary, want robustness to points far from it, or plan to kernelise for nonlinearity. Their linear boundaries are often similar.

7. Your model has 99% accuracy but is useless. What happened and what do you do?
Almost certainly severe class imbalance: predicting the majority class scores high accuracy. Switch to precision/recall/F1, PR-AUC, and log-loss; use class weighting or resampling; and set the decision threshold from the cost trade-off; the default of 0.5 is rarely appropriate.

8. Why standardise features, and is it ever unnecessary?
Necessary for regularised logistic regression (the penalty is scale-dependent) and for stable/fast gradient convergence. For unregularised MLE it doesn't change the fitted probabilities (rescaling a feature just rescales its coefficient), so it's optional for correctness there, though still helpful numerically.

9. How does logistic regression relate to a neural network?
It is a single neuron: an affine map $x^\top\beta$ followed by a sigmoid, trained with cross-entropy by gradient descent. Stack such units with hidden layers and nonlinearities and you get an MLP; the softmax output layer of a classifier net is multinomial logistic regression.

10. Is logistic regression well-calibrated, and why?
Typically yes, because it directly maximises the Bernoulli likelihood, which is a proper scoring rule minimised at the true conditional probabilities. Under model misspecification or heavy regularisation calibration can degrade; check with a reliability diagram and, if needed, apply Platt/isotonic calibration.

11. (Debugging) Coefficients are enormous with huge standard errors. Diagnose.
Likely (quasi-)perfect separation or severe multicollinearity. Check separability (does some feature perfectly split classes?), inspect VIFs, add $\ell_2$ regularisation, and verify the solver converged (raise max_iter, scale features).

12. Derive the decision boundary and explain its shape.
Classify positive when $\sigma(x^\top\beta)\ge0.5\Leftrightarrow x^\top\beta\ge0$. The set $x^\top\beta=0$ is a hyperplane with normal $\beta_{1:p}$; hence a linear boundary. Adding polynomial/interaction features makes it curved in the original space while staying linear in the expanded space.

25. Common Misconceptions

  1. "Logistic regression is a regression algorithm." The name refers to the regression of log-odds on features; it is used for classification. Its output is a probability, thresholded to a label.
  2. "The coefficients give the change in probability." They give the change in log-odds; the effect on probability is nonlinear (largest near $p=0.5$, negligible near $0$ or $1$). Exponentiating gives an odds ratio, still not a probability change.
  3. "The 0.5 threshold is fixed/optimal." It's an arbitrary default. The optimal threshold depends on class balance and the relative cost of false positives vs false negatives, and should be chosen from a validation ROC/PR curve.
  4. "Because the boundary is linear, the model is linear in $x$." The probability is a nonlinear (sigmoid) function of $x$; only the log-odds and the boundary are linear. And with engineered features the boundary itself can be highly nonlinear.
  5. "More features / bigger coefficients always mean a better fit." Unregularised logistic regression will happily drive coefficients to infinity under separation, giving a perfect training fit and poor generalisation. Regularisation and honest validation are essential.
  6. "A high AUC means good probabilities." AUC measures ranking, not calibration; a model can rank perfectly yet output systematically mis-scaled probabilities. Check calibration separately.

26(s). Solutions

Level 1

  1. Probabilities live in $[0,1]$ but a linear predictor ranges over all of $\mathbb{R}$; the log-odds also range over all of $\mathbb{R}$, so equating log-odds to a linear function matches the ranges and guarantees valid probabilities after inverting through the sigmoid.
  2. Unbounded predictions (impossible probabilities) and heteroscedastic Bernoulli errors that invalidate OLS inference (also: constant marginal effect on probability is implausible).
  3. Each one-unit increase in the feature multiplies the odds of the positive class by $0.5$: it halves the odds, i.e. is protective/negatively associated.
  4. Logistic regression maximises the Bernoulli likelihood (a proper scoring rule), which is minimised at the true probabilities, so its outputs behave like probabilities; SVM minimises hinge loss, which targets the margin, not probability, so its scores need post-hoc calibration.
  5. Heavy class imbalance (e.g. 1% fraud): "predict all negative" gives 99% accuracy but zero recall. Use precision/recall/F1 and PR-AUC (and log-loss).

Level 2

  1. $e^{\eta}=\frac{p}{1-p}\Rightarrow p=\frac{e^\eta}{1+e^\eta}=\frac{1}{1+e^{-\eta}}$. Then $\sigma'(\eta)=\frac{e^{-\eta}}{(1+e^{-\eta})^2}=\sigma(\eta)\cdot\frac{e^{-\eta}}{1+e^{-\eta}}=\sigma(\eta)(1-\sigma(\eta))$.
  2. $\frac{\partial\ell_i}{\partial p_i}=\frac{y_i-p_i}{p_i(1-p_i)}$; $\frac{\partial p_i}{\partial\eta_i}=p_i(1-p_i)$; $\frac{\partial\eta_i}{\partial\beta}=x_i$. Product: $\frac{y_i-p_i}{p_i(1-p_i)}\cdot p_i(1-p_i)\cdot x_i=(y_i-p_i)x_i$; sum $=X^\top(y-p)$.
  3. $\nabla^2\ell=\frac{\partial}{\partial\beta}\sum_i(y_i-p_i)x_i=-\sum_i p_i(1-p_i)x_ix_i^\top=-X^\top SX$. For any $v$, $v^\top X^\top SXv=\sum_i p_i(1-p_i)(x_i^\top v)^2\ge0$, so $-\nabla^2\ell\succeq0$: the loss $-\ell$ is convex.
  4. $\beta^{(t+1)}=\beta^{(t)}+(X^\top SX)^{-1}X^\top(y-p)$. Writing $z=X\beta^{(t)}+S^{-1}(y-p)$ (the "working response"), the update equals $(X^\top SX)^{-1}X^\top S z$, the weighted least-squares solution with weights $w_i=p_i(1-p_i)$, largest near $p=0.5$.
  5. $\eta=-1+2(1.5)=2$; $p=\sigma(2)\approx0.8808$; with $y=0$, $(y-p)=-0.8808$, so the gradient contribution is $-0.8808\cdot(1,\,1.5)=(-0.8808,\,-1.3212)$, pushing both coefficients down to reduce the over-prediction.

Level 3

  1. With $\lambda=0$ on separable data, $\|\beta\|$ grows every iteration (no convergence, probabilities collapse to 0/1); with $\lambda>0$ the objective $-\ell+\frac\lambda2\|\beta\|^2$ is strictly convex and coefficients settle at finite values.
  2. Accuracy stays high and flat; F1/PR-AUC reveal the true minority-class performance; sweeping the threshold traces the precision–recall curve; lowering it raises recall and lowers precision. Pick the point matching your cost ratio.
  3. Plain logistic gives a straight boundary that misclassifies the interleaved moons; adding polynomial/interaction features bends the boundary to separate them, at the cost of higher variance (regularise/validate).
  4. Bin predictions and plot observed vs predicted frequency; if the curve sags away from the diagonal, isotonic/Platt calibration on a held-out set pulls it back towards the diagonal and lowers log-loss/Brier.
  5. Report $e^{\hat\beta_j}$ and $\exp(\text{CI})$; the two predictors with ORs farthest from 1 (and CIs excluding 1) are the most influential. Interpret each as a multiplicative change in odds per unit feature.
